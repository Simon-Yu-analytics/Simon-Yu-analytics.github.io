The decision problem

How can an operations team connect complaint routing, future demand, and staffing assumptions in one inspectable workflow?

ComplaintOps is an independent analytics prototype. It routes complaint text, forecasts weekly product queues, and translates demand uncertainty into capacity scenarios. Its committed benchmark uses 6,165 synthetic complaints over 52 weeks.

A connected analytical workflow

Complaint textRouting + reviewQueue forecastCapacity scenario
  1. Route with an interpretable baseline. A multinomial Naive Bayes model uses chronological train, calibration, and test windows containing 3,673, 935, and 1,557 cases.
  2. Separate confidence from automation. Select a confidence threshold on the calibration window for an 85% accuracy target, then freeze it for final-period testing. Uncertain cases go to human review.
  3. Compare queue forecasts. Evaluate last-value, four-week average, eight-week average, and local-trend baselines with walk-forward WAPE. Select a method separately for each queue.
  4. Expose capacity assumptions. Use 80% forecast upper bounds and explicit productivity and cost inputs. The browser application allows scenario changes.

These metrics describe the final chronological holdout of the synthetic sample. Under the frozen policy, the remaining 15.9% of test cases are assigned to human review.

The selected queue forecasts average 9.3% WAPE. This is the walk-forward model-selection score, not a separate final holdout estimate. The staffing scenario yields nine agents under the stated dedicated-team and productivity assumptions.

Prototype and reproducibility

The repository includes a Python pipeline, a deterministic sample generator, model and report artifacts, tests, and a responsive six-view browser application. The application links intake routing with triage evaluation, demand forecasting, and workforce planning.

Demo cases and feedback remain in the visitor’s browser. The prototype does not send real support requests or represent a live financial service.

Limitations and what I learned

Synthetic data demonstrate the software workflow; they do not establish performance on real complaints. Routing scores are not guaranteed calibrated probabilities, and forecast intervals do not capture structural shocks.

The capacity model assumes dedicated teams and fixed productivity. Production planning would require service-level targets, scheduling, backlog, shrinkage, and cross-trained staff.

Takeaway: model accuracy becomes more useful when it is accompanied by automation coverage, an explicit review path, and visible planning assumptions.
